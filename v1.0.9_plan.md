## Implementation Plan

### Phase 0: Testing Infrastructure (New - Testing/Development)
**Estimated**: 2-3 hours

#### 0.1 Source Path Selection UI
- Add "Choose Scan Source" screen before FileTypes
- Show file browser to select single folder instead of auto-detecting
- Allow quick testing with small subsets instead of full cloud sync
- Store last selected path in preferences
- **Impact**: Enables fast iterative testing without full OneDrive sync
- **Files to modify**: 
  - `src/components/SourcePath/index.tsx` (new)
  - `src/App.tsx` (add routing)
  - `src/store/index.ts` (persist selected path)
  - `src-tauri/src/commands/mod.rs` (update scan entry point)
- **User Benefit**: Testers can target single folders, faster feedback cycles

### Phase 1: Backup Robustness (Critical)
**Estimated**: 4-6 hours

#### 1.1 ZIP Integrity Validation
- Add ZIP CRC validation function
- Validate manifest.json checksum on backup open
- Return clear error if ZIP corrupted
- **Files to modify**: `src-tauri/src/backup/mod.rs`

#### 1.2 File Move Verification
- Compute hash AFTER move
- Compare with manifest hash
- Log mismatch as critical error
- **Files to modify**: `src-tauri/src/restructure/mod.rs`

#### 1.3 Disk Space Check
- Get AppData partition free space
- Estimate backup size from file list
- Warn user if insufficient space
- **Files to modify**: `src-tauri/src/backup/mod.rs`, `src-tauri/src/commands/mod.rs`

### Phase 2: OCR Integration (High Priority)
**Estimated**: 6-8 hours

#### 2.1 Tesseract Integration
- Add tesseract-ocr crate to Cargo.toml
- Replace OCR stub with real extraction
- Handle image preprocessing (rotate, denoise)
- **Files to modify**: 
  - `src-tauri/src/classifier/extractor.rs`
  - `src-tauri/Cargo.toml`

#### 2.2 OCR Error Handling
- Gracefully handle unreadable images
- Log OCR failures per file
- Fall back to filename-based classification
- **Files to modify**: `src-tauri/src/classifier/mod.rs`

#### 2.3 Performance Optimization
- Add OCR timeout (5s per image)
- Batch OCR processing
- Cache extracted text
- **Files to modify**: `src-tauri/src/classifier/mod.rs`

### Phase 3: Cloud Detection Improvement
**Estimated**: 3-4 hours

#### 3.1 Multi-Cloud Detection
- Expand registry checks (Google Drive, Dropbox)
- Add environment variable detection
- Check common mount points
- **Files to modify**: `src-tauri/src/cm_registry.rs`

#### 3.2 User Cloud Path Configuration
- Allow manual cloud path specification
- Save to config file
- Use in subsequent scans
- **Files to modify**: `src-tauri/src/cm_registry.rs`, UI components

### Phase 4: Performance & Error Handling
**Estimated**: 4-5 hours

#### 4.1 Large File Handling (>10k files)
- Add pagination to scanner
- Stream classification results
- Limit memory usage
- **Files to modify**: `src-tauri/src/scanner/mod.rs`, `src-tauri/src/commands/mod.rs`

#### 4.2 Granular Error Messages
- Replace generic "File access failed" with specifics
- Include permission status
- Suggest remedies
- **Files to modify**: `src-tauri/src/scanner/mod.rs`, error handling throughout

#### 4.3 Manifest Directory Creation Optimization
- Batch create all directories upfront
- Reduce per-file overhead
- **Files to modify**: `src-tauri/src/restructure/mod.rs`

### Phase 5: Testing & QA
**Estimated**: 2-3 hours

#### 5.1 Unit Tests
- Backup ZIP validation tests
- OCR extraction tests
- File move verification tests
- Error handling edge cases

#### 5.2 Integration Tests
- Full scan → classify → restructure → restore cycle
- Large file count (10k+) stress test
- Cross-filesystem restore
- Corrupted backup recovery

#### 5.3 Manual Testing
- UI workflow testing (scan, classify, preview, confirm, restore)
- Cloud detection on user's system
- Backup size estimation accuracy

## Rollback Plan

If critical issue found in v1.0.9:
1. Keep v1.0.8 installers available
2. Tag v1.0.9 as "pre-release" initially
3. If needed, jump to v1.0.10 with fix
4. Never release v1.0.9 with known critical bugs

## Git Strategy

- Branch: `feature/v1.0.9` from `master`
- Merge back to `master` only after QA passes
- Tag: `v1.0.9` on merge commit
- Keep separate release folder for installers
